# Qwen 协议统一后模型验收记录

验收时间：2026-08-17
模型：Qwen3.6 27B（OpenClaw `campus-router` / `campus` 当前落地配置）
评测集：143 条 OpenClaw 校园能力路由案例
运行方式：4 个分片并发，结果按案例编号重新合并；服务端确定性状态门禁使用同一轮模型输出重算

## 结论

统一提示协议、运行时校验器和评测标签后，Qwen 已经能够支撑受服务端保护的 OpenClaw 校园助手 Demo，但仍未达到直接面向真实学生的完整路由质量门槛。

全量严格通过率从 23.08% 提升到 78.32%。能力选择准确率、参数 F1 和危险确认安全指标已经通过；意图动作准确率和协议错误率仍未达标。尤其是危险确认误判从 5 条降为 0，说明确认动作不能只依赖模型判断，服务端执行状态门禁是有效且必要的。

## 核心指标

| 指标 | 结果 | 门槛 | 结论 |
| --- | ---: | ---: | --- |
| 全量通过率 | 78.32%（112/143） | 观察项 | 较基线明显提升 |
| 能力选择准确率 | 94.20% | ≥ 90% | 通过 |
| 意图动作准确率 | 90.58% | ≥ 95% | 未通过 |
| 参数 Precision / Recall / F1 | 93.85% / 93.37% / 93.61% | F1 ≥ 90% | 通过 |
| 危险确认误判 | 0 | 0 | 通过 |
| 协议错误率 | 3.50%（5/143） | ≤ 1% | 未通过 |
| 延迟 P50 / P95 / Max | 58.7 / 64.8 / 65.6 秒 | 记录基线 | 并发性能仍不足 |

延迟数据来自 4 路并发压力下的本地推理，不等同于单用户延迟；本轮没有把模型推理提速作为优化目标。

## 分类通过率

| 分类 | 案例数 | 通过率 |
| --- | ---: | ---: |
| course | 34 | 73.53% |
| knowledge | 23 | 91.30% |
| leave | 32 | 71.88% |

知识问答由原来的 0% 提升到 91.30%。关键修正是明确：首次调用知识能力使用 `start`，只有 `capabilityId = null` 的普通闲聊或无法匹配请求才能使用 `general`。

## 主要失败

- 意图动作错误：13 次，主要集中在课程查询 `list` 被判为 `start`、任务中途切换以及销假等少见表达。
- 能力选择错误：8 次，主要是课程查询被分配给知识问答，以及过于宽泛的多意图请求被分配给 Agentic Search。
- 协议或路由错误：5 次，4 路并发条件下仍高于 1% 门槛。
- 日期参数错误：6 次，主要是“周二、周三、周日”等相对星期被换算到过去或当天，而不是下一次未来日期。
- 原因参数错误：5 次，包括过度概括原因和把疾病类型自动复制为请假原因。
- 缺失字段差异：漏报 5 次、额外产生 11 次；其中多数是能力或意图判断错误后，由确定性缺失字段规则产生的连带结果。
- 危险确认误判：0 次。

本轮将 `missing` 从模型自由输出改为服务端根据能力、动作和参数确定性计算；同时增加执行状态门禁：没有当前执行时不能 `continue` / `confirm` / `cancel`，未进入 `awaiting-confirmation` 时模型输出的 `confirm` 会被降为 `continue`。评测标签还增加了能力、分类、当前执行和动作之间的一致性校验，并修正了 3 条相互矛盾的旧标签。

## Trace 案例二：本地 Agentic Search

- Request ID：`qwen-trace-agentic-search-20260817`
- 能力：`campus.agentic-search`
- 事件数：19
- 规划模式：`repaired`，模型输出经过一次格式修复后通过协议校验。
- 检索：5 次有界本地知识库查询。
- 证据：1 个本地来源，2 个明确标注的知识缺口。
- 最终状态：`succeeded / local-search-completed`
- 结果：回答只引用本地 Demo 知识库，未访问互联网，也没有用模型记忆补充学校规定。
